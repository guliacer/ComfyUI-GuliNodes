# GG 耗时

## 目标与边界

- 新增稳定 ID `GGWorkflowTimer`，显示名 **GG 耗时**，分类 `GuliNodes/工作流`。
- 放到画布即可显示本次工作流总用时和耗时最长的三个节点及各自用时，无接线、无执行副作用、无额外 Python 依赖。
- 一个「展示内容」选择器：全部（默认）、总用时、耗时最长的三个节点。
- 与 GG 标题共用字体、文字/背景颜色、粗斜体、装饰、字距、对齐、内边距、圆角、旋转和透明度；动态统计文本只读。
- 使用既有标题工具栏、Canvas/Nodes 2.0 绘制与放置机制，不复制标题扩展。
- 宽高归用户；新建时允许按内容定一次默认尺寸，运行刷新/切换展示内容/读档保持尺寸，拖拽最小尺寸为常数。

## 计时口径

- 总用时从 execution_start 到成功、失败或中断，不含排队；最终优先用服务器毫秒时间戳差，运行中用单调时钟。
- 逐节点优先使用原生 progress_state 的 running/finished 边界，涵盖无 UI 输出、异步节点和动态展开。旧前端缺失该事件时使用 executing 切换边界。
- 不把 executed 当作通用完成信号，不把缓存回放记成执行耗时。
- 同一画布节点的动态子执行取时间区间并集（非重叠段累计），按耗时降序取前三；显示节点名及 ID 区分同名节点。
- 按 prompt_id 和提交时的画布节点快照隔离；切工作流、排队、多次运行、延迟消息不串数据。
- 没有记录时显示等待；缓存全部命中显示无实际执行节点；失败/中断冻结已有统计。
- 仅完成的精简统计随节点 properties 保存，不落插件目录、不持久化活动时钟。

## 验收

## UI 增量（2026-11-14 用户追加）

- 保留既有后端定义、progress_state 采集、区间并集计时和 summary 数据结构；只换展示层。
- 默认跟随宿主明暗主题的紧凑卡片（深色暗底浅字、浅色白底深字），固定 GG 耗时标题和已有状态，宽节点左右分栏、窄节点上下排。
- 总用时采用 8.42s / 12m 48s / 1h 12m 30s；装饰圆环不代表未知的执行进度。
- Top3 显示真实节点名、用时和以最长项为 100% 的比例条，蓝 / 紫 / 青绿区分；不足三项不补项，空记录写「暂无耗时数据」。
- 新建默认尺寸可按面板内容设一次；已有节点尺寸不被运行、换显示、读档或样式更新收回。显式「适配」更新用户尺寸副本。
- 复用标题工具栏和 Canvas / Nodes 2.0 入口，通过呈现钩子扩展，不增加第三方图表依赖；色值只在 GG 设计系统维护。
