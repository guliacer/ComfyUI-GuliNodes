# GG 人像 / 背景分区编辑：使用说明

## 这份工作流做什么

[工作流 JSON](<GG-人像背景分区编辑_Qwen2.1_Turbo.json>)把画面分为人像、背景两个编辑区域，**先处理人像，再对处理后的图像取反蒙版处理背景，两段串行累加出图**。人像蒙版默认由 **SAM3 文本识别自动生成**（提示词 `person`，无需手画），也可以一键切回手绘蒙版。借鉴的是孤海工作流的“蒙版裁剪 → 局部处理 → 原坐标还原”思路，实际节点采用 GG、Easy-Sam3 与 ComfyUI 原生能力。

**蒙版来源二选一**（节点“自动识别人像（关掉=用手绘蒙版）”）：
- **开（默认）**：`easy sam3ImageSegmentation` 用文本 `person` 自动框出人像，秒级出蒙版，适合大多数单人照片；想识别特定目标可把提示词改成 `woman`、`dancer` 等英文描述。
- **关**：走原来的手绘蒙版（右键加载图像 → 遮罩编辑器涂人物），适合自动识别失败（多人、被遮挡、人物很小）或想精确限定范围时。两种方式最终都汇入同一个「蒙版来源：自动 / 手绘」开关，下游完全一致。

**依赖**：自动识别需要 `ComfyUI-Easy-Sam3` 插件和 `models/sam3/sam3.pt`（SAM3 权重，约 3.5 GB）。没有这些就把开关关掉，工作流其余部分照常运行。SAM3 以 fp16 加载，识别完即可释放显存，不会与后面的 Qwen turbo 争显存。

- 分别填写人像、背景修改需求。
- 清空任一区域需求（只留空格也算空）就跳过其整条优化、编码与采样，直接使用该阶段输入。
- **先人像后背景的串行两段**：先识别人像蒙版 → 提示词优化 → 只在人像蒙版内处理，得到「人像已优化」的图；再对这张图取反蒙版（背景遮罩）→ 提示词优化 → 只处理背景。背景阶段基于已优化的人像，光影色调会与之协调，贴回后自然完成融合。
- 两路都使用完整画面作为 AI 优化上下文，不把人物抠成黑底后单独重新摆放。
- 按原像素裁剪、保持原图比例，处理后回到原画幅、原位置。
- 图像 Latent 来自原图 VAE 编码，附区域噪声蒙版，不使用空 Latent 从头生图。
- 解码后仍按原蒙版再次限制贴回范围，避免只依赖采样噪声蒙版。
- 以人物身份、姿态、位置、比例、外轮廓基本不变为目标；这不是姿态锁定模型，人物内部几何仍可能发生变化。

## 首次运行

1. **重启 ComfyUI**，让新增的 `GG 分区编辑准备` 加入后端注册；刷新网页。仅刷新网页不能加载新的 Python 节点。
2. 导入上面的工作流 JSON，或者在工作流列表打开安装时放入的同名工作流。
3. 在左侧“上传原图”节点选择你自己的照片。
4. **蒙版**：默认不用动手——SAM3 会自动识别人像；想看识别结果就跑一次“① 蒙版诊断”。要手画就把“自动识别人像”开关关掉，右键“加载图像” → **遮罩编辑器**涂选人物并保存。
5. 查看左侧蒙版预览：**白色应为人物，黑色应为背景**。普通 RGB 图片、或 Alpha 全不透明的 PNG 不含有效选区；这种情况会报中文错误，不会继续生成。
6. 分别修改“背景修改需求”和“人像修改需求”。只改人物时，把背景需求彻底清空；只改背景时，清空人像需求。
7. 先保持 AI 优化开关关闭，确认蒙版和小幅编辑流程。需要自动改写需求时开启“启用 AI 提示词优化”；配置见下节。
8. 点击运行，查看右侧“最终结果 ↔ 原图”，PNG 保存在 ComfyUI 输出目录按日期创建的 `GG_人像背景分区` 文件名前缀下。

**手绘不是自动分割。** 发丝、衣服边缘、人物手指之间的背景留白需要自己检查。背景蒙版由人物蒙版反相得到，不能再单独画另一份边界不同的背景蒙版。

## 先看蒙版诊断，再跑生成

工作流加载图像后接了一个 **`GG 蒙版诊断`** 分支（节点「① 蒙版诊断」），秒级完成、不加载模型。它做两件事：

1. **把识别结果画出来**：人物有效区染成青绿色、背景轻微压暗。**青绿落在人身上才算涂对**；青绿跑到背景上 = 涂反了；整张几乎没青绿 = 没涂上或笔刷太细。
2. **给出中文诊断**：尺寸是否一致、人物/背景各占多少、有效区平均权重、结论（可用 / 不可用 + 改法），显示在下方的「蒙版诊断说明」节点上。

看到「结论：可用」再跑后面的生成；报错时诊断文本里的占比数字就是原因（0.00% = 没涂上、<0.2% = 太小或涂反、100% = 涂满全图）。

自动识别失败时的处理顺序：① 把 SAM3 提示词改得更具体（如 `woman sitting on chair`）；② 降 `threshold`（默认 0.4，可到 0.3）；③ 关掉自动开关改手绘。

## 蒙版报错怎么看

报错会**直接画在失败节点的下方**（红底白字，重启网页后首次生效），同时右上角弹出通知，不需要翻运行日志。运行被拦下时，按报错里的实际统计数字对号入座即可：

| 报错关键词 | 含义 | 怎么改 |
| --- | --- | --- |
| `人像遮罩为空` | 图像没有进过遮罩编辑器，传上来的是 64×64 全黑占位蒙版 | 右键加载图像 → 遮罩编辑器，涂选人物并保存 |
| `全部为黑色（有效区域 0.00%）` | 进过编辑器但人物选区没有保存成功 | 重新涂选，保存后确认文件名变成 `clipspace-painted-masked-*.png` |
| `有效区域仅 0.xx%（不足 0.2%）` | 涂选范围过小，或人物与背景涂反 | 看蒙版预览：白色应是人物。若白色是背景，重新涂人物；涂选要覆盖人物主体，不要只描一条轮廓线 |
| `100.00%（全白）` | 整张图都被涂成人物 | 编辑器里只涂人物，背景保持黑色（可用大笔刷先清空再涂） |
| `尺寸 … 与图像 … 不一致` | 遮罩和图像不是同一张 | 用同一图像的遮罩编辑器重新涂选并保存 |

有效区域按「权重高于 0.1 的像素」统计，占比小于 0.2% 一律拦截，防止下游裁剪误退化为整图重绘。涂选正常但报 `0.00%` 多半是保存没生效：关掉编辑器后重新进入，确认预览里人物是白色再点保存。

## 两路提示词怎么写

### 人像需求示例

> 仅优化人物皮肤层次、发丝和服装质感，保留真实自然细节，不改变脸型、身份、姿态、位置、比例和外轮廓。

适合肤质、材质、服装纹理和小幅明暗变化。不适合换姿态、移动人物、改变发型或服装外轮廓。

### 背景需求示例

> 保持场景结构与物体位置，只优化背景的曝光层次、色彩和材质细节，使画面更自然干净。

需要保留人物时不要在这里要求改变人物动作。接触阴影、地面投影或反射属于背景，必要时明确写进需求；只改人物轮廓内部并不能自动协调这些区域。

### 共同摄影要求

左侧共同要求会传给两路，例如：

> 保持原画幅、机位、透视和摄影风格。人物与背景的主光方向、色温和明暗关系协调，不新增人物，不改变构图。

准备节点独立输出固定保护约束；即使 AI 改写省略了这些约束，工作流也会在改写后再次追加它们。**是否编辑只看原始区域需求，不看追加后的约束文本。**

## 可选 AI 提示词优化

- 工作流每区各有一个 `GG 提示词增强qwen2.1`，输出的是需求文本。
- `GG 提示词优化qwen2.1` 则是 Qwen 图像 / 文本条件编码节点，名称相近，但它不负责 LLM 改写。
- AI 开关关闭时，原生懒求值开关直接用区域请求，不会调用本地 LLM 或任何 API；开关开启时才调用增强节点。
- 本机预选本地LLM路径，文生图与图生图分别用 PE-T2I / PE-I2I GGUF，图生图另配 I2I 的 mmproj；这些是 GGUF 模型。「本地PE」方式另用上游 `CLIPLoader` 加载 Qwen Image PE safetensors，不要把 GGUF 填进 `CLIPLoader`。
- 本地LLM仍依赖已有可选包 `llama-cpp-python`，主插件没有新增强制依赖。其它计算机需配置自己的兼容模型或保持开关关闭。
- 本地LLM通过独立子进程运行，避开 PyTorch 与视觉库的 OpenMP 冲突；不要设置 `KMP_DUPLICATE_LIB_OK` 来强行忽略冲突。工作流默认「卸载策略 = 自动」：显存吃紧时运行后卸载，释放 LLM 显存后再继续扩散；也可以显式改成「运行后自动卸载」。改成「保持加载」会保留 LLM 进程和显存，16GB 显卡跑本工作流不建议这样设置。
- 不随工作流嵌入 API Key。不使用本地模型时，可以手动选择支持图像的 API 并自行配置密钥；未配置就不要开启该通路。

## 降噪怎么调（最重要）

流程是「裁剪 → 局部重绘 → 原坐标贴回」，改动幅度几乎全由 KSampler 的 `降噪强度` 决定。Qwen 2.1 turbo、9 步、CFG 1.0、1080×1920 实测标定：

| 降噪 | 与原图差异（全图平均） | 观感 |
| --- | --- | --- |
| 0.25 | 约 3/255 | 几乎看不出变化，等于白跑 |
| 0.45 | 约 5/255 | 只有极轻微质感变化 |
| 0.6 | 约 8.5/255（背景区 8.9） | 水面高光、树影层次、材质明显改善 |
| 0.8 | 明显重绘 | 变化大，人物容易走样，建议只用于背景 |

- 想要更明显：背景 0.7、人像 0.45，再高人物容易变形。
- 想更保守：背景 0.5、人像 0.3。**低于 0.4 基本看不出变化**——这是旧版"跑完没效果"的直接原因。
- 裁剪尺寸过去固定 768×768 正方形，会把竖图压扁 2.5 倍，采样后拉伸回来改动被稀释（同样降噪 0.45 只剩 2.3/255）。现在改为「原像素」保持比例；代价是采样按原图尺寸跑，1080×1920 约 40–60 秒。**超大图（长边超 2000）建议先缩小再跑**，否则显存和耗时都会吃紧。
- 想要更快但仍是正确比例：把裁剪节点「输出尺寸」改成「按边长」+ 匹配你照片的比例（如 9:16），边长 768。

## 安全限制与常见问题

- **只支持单张图片。** 多张批次先拆分，避免不同人像蒙版复用同一裁剪区域。
- 图像与有效人物蒙版必须同尺寸、数值有限且在 0–1。
- 人物与当前目标区域按 `MASK > 0.1` 的有效像素占比至少 0.2%；全白人物蒙版拒绝。还需通过下游裁剪的 float32 有效面积检查，避免极端精度变化触发整图回退。
- 普通加载图像的 64×64 全黑占位会提示先涂选并保存，不会静默缩放或反相变成全白背景。
- 背景生成结果同时连接到人物阶段的准备、恢复底图与最终合并底图，不要把它们改回旧原图，否则会丢失已修改的背景。
- 不要给被跳过的编辑分支另接独立的保存 / 预览输出节点；它们可能变成执行根，使该分支仍被运行。
- 最终原蒙版的全黑区域保留当前阶段底图；软灰边缘属于混合带。PNG 是无损保存，但模型重绘、VAE 和缩放本身不是无损修图。
- 出现“缺少节点”时先重启后端并刷新，再检查 GuliNodes 是否导入成功。

## 验证范围

交付前通过 104 项测试，真实注册 45 个后端节点且无失败模块；V3/legacy、蒙版数据、裁剪/还原/限域、独立进程错误/超时/清理与工作流连线均已验证。真实 Chrome 前端导入和 API 参数校验通过；无需求可直接保存原图、空蒙版会在加载模型前拒绝。

另分别完成两项实际模型测试：

- 背景→人像两轮扩散，均 9 步、降噪 0.6/0.35、原像素裁剪，1080×1920 约 42–60 秒，输出与原图同尺寸 PNG；实测背景区平均改动 8.9/255、人像区 7.3/255，画面可用、无接缝（测试图为矩形人工蒙版）。
- 对照实验：降噪 0.25 → 差异 3/255（近似直通）；0.45 → 5/255；0.6 → 8.5/255；把裁剪固定 768×768 正方形会把竖图改动稀释到 2.3/255。
- 隔离后的本地 PE-I2I 视觉改写成功，实际 Qwen3.5 模型读取照片缩小参考图并返回中文区域编辑请求，约 24.67 秒，无 OpenMP 崩溃。

这两项是分别测试，并非整套“AI开启＋两阶段扩散”一次性端到端测试；没有替用户重启正在运行的 ComfyUI。扩散结果保持大体构图与姿态，但有细节软化和五官/纹理变化，不能保证绝对身份、姿态保真或画质提升。
